# Markdown standards

- Put blank lines before and after headings, except that a first-line heading needs no preceding blank line. Separate tables and fenced code blocks from surrounding text with blank lines.
- Keep each prose paragraph on a single line; do not hard-wrap paragraphs to a fixed column width. Preserve intentional list structure and hard breaks.
- Use descriptive relative links and verify paths/anchors from the document's own location. Keep code examples short, accurate, and free of credentials or developer-specific absolute paths.
- Use concise Keep a Changelog entries grouped by change type. Distinguish planned work, completed work, and verified results; do not change historical release dates or versions incidentally.
- Preserve project-specific documentation and glossary policies. If a repository maintains an acronym glossary, check it before introducing terms and update it when required; do not require an Atlas-only glossary in every repository.
- Follow the repository's action-item location and numbering policy. Avoid duplicating the same backlog across documents.
